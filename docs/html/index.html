Register Allocator Architecture & Implementation

Project Overview

This project implements a sophisticated Graph-Coloring Register Allocation suite designed for modern compiler backends. It transforms variable live ranges into a Web-based Interference Graph and provides four distinct allocation strategies ranging from simple greedy heuristics to advanced hybrid models with exhaustive structural optimization.

Usage Instructions

Building the Project

The project uses a standard Makefile. To build the executable:

make

This will generate the myProg binary in the root directory.

Batch Mode

Designed for automated processing and performance evaluation.

./myProg -b <ranges_file> <config_file> <output_file>
  • ranges_file: Path to the variable live ranges.
  • config_file: Path to the register and algorithm configuration.
  • output_file: Path where the allocation report will be saved.

Interactive Mode

Provides a user-friendly menu to load files and select algorithms manually.

./myProg

Follow the on-screen prompts to configure and run the allocation.

Testing and Validation

The project includes a comprehensive automated test suite to ensure the technical integrity and output correctness of all allocation algorithms.

Running the Tests

You can execute the test suite using the provided script:

./tests/run_tests.sh all # Run the full suite (88 test cases)
./tests/run_tests.sh smoke # Run only error-handling/smoke tests
./tests/run_tests.sh free # Run only Free algorithm tests
./tests/run_tests.sh ranges # Run all ranges against all algorithms

Validation Criteria

A test is marked as Passed only if it satisfies the following structural requirements:

  1. Zero-Crash Execution: The program must exit with code 0.
  2. Artifact Generation: The script verifies the creation of the report (.txt), the interference graph (.gv), and the allocated graph (_allocated.gv).
  3. Format Compliance: The output text is scanned via grep to ensure it strictly follows the project specification.
  4. Graph Validity: DOT files are checked for valid Graphviz headers to ensure visualization compatibility.

Allocation Architectures

1. Basic Allocator (Greedy Simplification)

The foundational algorithm based on Chaitin's graph simplification.

  • Core Principle: A graph is \(N\)-colorable if we can iteratively remove nodes with degree \(< N\).
  • Process: Nodes with degree \(< N\) are pushed onto a stack.
  • Failure Mode: If all remaining nodes have degree \(\geq N\), the allocator terminates as unfeasible.
  • Coloring: Pops nodes from the stack and assigns the smallest available register index [0, N-1].

2. Spilling Allocator (Load/Store Fallback)

Extends the Basic Allocator with a recovery strategy to ensure 100% completion rate.

  • Recovery Logic: When stuck (all nodes \(\geq N\)), it selects a "victim" node to move to memory (Spill).
  • Heuristic:
    • Primary: Highest Degree (removes the most interference edges).
    • Secondary (Tie-breaker): Smallest Footprint (minimizes data movement costs by picking nodes with fewer definitions and last uses).
  • Result: The victim is marked as Memory (M) and the graph is simplified again.

3. Splitting Allocator (Structural Optimization)

A structural alternative to spilling that attempts to keep variables in registers by fragmenting their live ranges.

  • Exhaustive Brute-Force Search: Instead of arbitrary mid-point splitting, this implementation runs a full simulation for every possible split point.
  • The "Best Point" Heuristic: For each potential split, it rebuilds the graph and runs a "Simplified Colorability Test."
  • Evaluation Metric: It selects the split point that minimizes the number of "stuck" nodes (degree \(\geq N\)).
  • Cycle Breaking: This approach is uniquely capable of breaking complex interference Cycles (like the 5-cycle) without requiring any memory spills.

4. Free (Hybrid) Allocator (Expert Decision Tree)

The most intelligent tier, combining global analysis with high-end heuristics.

The Decision Loop:

  1. Clique Detection (Fail-Fast): Runs a greedy clique finder. If a clique of size \(N+1\) is found at any program point, it spills the node with the highest degree within that clique instantly.
  2. DSATUR Coloring: Uses the Degree of Saturation algorithm. It prioritizes nodes based on neighbor constraints, finding optimal colorings for dense graphs where greedy ordering fails.
  3. Advanced Splitting Fallback: If DSATUR fails to color all nodes, it triggers the Exhaustive Brute-Force Split logic for the uncolored node with the highest degree.
  4. Surgical Spill: If the split budget (limit of 3) is exhausted or splitting doesn't improve colorability, it performs a targeted spill and restarts.

Complexity Summary

The performance of each allocator is determined by the number of variables ( \(W\)), the length of live ranges ( \(L\)), and the total number of interferences ( \(E\)).

Algorithm Complexity Strategy Best Used For
Basic \(O(W^2 \cdot L \log L + E)\) Simple Greedy Low-pressure, linear code
Spilling \(O(W^2 \cdot L \log L + W^2 + E)\) Degree-based Spill Reliable general-purpose allocation
Splitting \(O(S \cdot L^2 W^2 \log L)\) Brute-Force Simulation Breaking complex interference cycles
Free \(O(C \cdot W^3 + S_{limit} \cdot L^2 W^2 \log L)\) Hybrid Decision Tree Maximum register utilization

For a more granular breakdown of internal functions (like interferesWith or findGreedyClique), please refer to the project's ALLOCATORS.md.
